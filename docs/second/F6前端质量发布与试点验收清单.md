# F6 前端质量发布与试点验收清单

> 更新时间：2026-08-24
>
> 适用分支：`enterprise/internal-dev`
>
> 覆盖范围：T0—T47 已落地能力的前端发布门禁，不代表 T48—T60 已完成

## 1. 阶段结论

F6 的工程化门禁已覆盖企业工作台核心流程、视觉基线、基础可访问性、页面性能、运行时异常、关键行为埋点和 viewer 只读权限。代码达到进入正式业务试点验收的技术条件；业务验收仍须由通用 PPT 试点 Owner、竞标项目 Owner、运维和安全负责人共同签字。

## 2. 自动化发布门禁

| 门禁 | 自动化内容 | 通过标准 |
| --- | --- | --- |
| 源码契约 | 工作区壳层、创建向导、资源治理、评审、竞标阶段与发布脚本 | 全部测试通过 |
| ESLint/TypeScript | 企业工作台与 E2E 新增代码 | 无错误 |
| 生产构建 | Next.js production build | 构建成功，企业路由完整生成 |
| 主流程 E2E | 通用创建、跨文稿评审、竞标六阶段、资源中心 | 全部通过 |
| 异常恢复 | API 500 错误可见，恢复后页面可重新使用 | 无白屏、无未处理异常 |
| 可访问性 | 按钮名称、图片替代文本、表单控件标签 | 基础扫描零问题 |
| 视觉回归 | 创建方式、确认创建两个稳定状态 | 像素差异比例不超过 1% |
| 性能预算 | TTFB、FCP、DOMContentLoaded、Load | 不超过默认预算 |
| 权限门禁 | 自动创建/复用 viewer，验证 UI 只读和服务端拒绝写入 | 写接口返回 403，或按防枚举策略返回 404 |
| 企业埋点 | 页面访问、空间切换、加载异常、运行时异常、创建请求/接受/失败 | 事件可采集且不含业务正文与标识符 |

执行命令：

```bash
cd servers/nextjs
npm run test:release-gate
```

仅在产品确认视觉变化后更新基线：

```bash
npm run test:e2e:enterprise:update
```

禁止为绕过失败直接更新截图；必须先确认变化符合设计预期，并在代码评审中同时审查旧、新截图。

## 3. 默认性能预算

| 指标 | 默认上限 | 环境变量 |
| --- | ---: | --- |
| TTFB / responseStart | 2500 ms | `PLAYWRIGHT_PERF_TTFB_MS` |
| First Contentful Paint | 4000 ms | `PLAYWRIGHT_PERF_FCP_MS` |
| DOMContentLoaded | 5000 ms | `PLAYWRIGHT_PERF_DCL_MS` |
| Load | 8000 ms | `PLAYWRIGHT_PERF_LOAD_MS` |

默认值用于共享预览环境，生产环境应在获得连续一周基线后按 P75 数据收紧。性能门禁失败时应记录页面、部署版本、浏览器、指标实测值和接口耗时，不允许仅扩大阈值。

## 4. 埋点和隐私边界

允许采集：

- 工作台路由、工作区类型、当前角色；
- 创建方式、页数、资料数量、是否配置受众与品牌规则；
- 操作是否接受、失败类型和异常通道；
- 不可逆推出业务内容的布尔值、枚举值和数量。

禁止采集：

- 工作区名称、用户名、用户 ID、工作区 ID；
- PPT 主题、提示词、资料正文、检索词、评审批注；
- 客户名称、项目编号、药品、适应症和交付文件名；
- Cookie、令牌、下载地址、对象存储 Key 和原始错误响应正文。

## 5. 通用 PPT 业务验收

- [ ] 用户可进入企业工作台并正确识别当前空间与角色；
- [ ] 主题、企业资料、企业模板、空白和导入五种创建入口语义清晰；
- [ ] 主题创建能够带入受众、页数、语言、语气、模板和品牌约束；
- [ ] 资料创建只展示有权访问且状态有效的版本，并保留来源引用；
- [ ] 文稿能够进入编辑、评审、整改、质量检查、冻结和交付流程；
- [ ] API 失败时用户看到可理解原因和恢复动作，不出现白屏；
- [ ] viewer 无法看到管理入口，直接调用写接口也被拒绝；
- [ ] 文档、模板、资产和交付中心的列表、详情、版本与治理动作可用。

## 6. 竞标 PPT 业务验收

- [ ] 能创建竞标项目并展示六阶段导航；
- [ ] 项目画像、资料和招标要求能够建立来源关系；
- [ ] 医学、运营、数统等专业模块能按角色协同；
- [ ] Gate 问题能够登记、分派、处理和留痕；
- [ ] 未通过门禁时不能冻结或交付；
- [ ] 组装版本能够锁定模块版本和来源 manifest；
- [ ] 竞标交付件授权、下载、撤销与证据查询可追溯；
- [ ] 通用工作台能力没有因为竞标流程而被限制或隐藏。

## 7. 运维与安全验收

- [ ] 管理员能够查看巡检批次、失败原因和完整性异常；
- [ ] 完整性异常能够隔离、复检、接受风险或标记误报；
- [ ] 高风险异常会暂停新增下载授权；
- [ ] 日志和前端埋点中不存在正文、凭据和长期下载链接；
- [ ] 数据卷备份、恢复和版本回滚在试点环境演练成功；
- [ ] 发布前确认数据库迁移方向、镜像版本和回滚镜像；
- [ ] 生产监控与外部告警能力列入 T48，不以现有前端埋点替代。

## 9. F6 后续衔接

F6 验收通过后进入 T48：企业监控与外部告警。T48 应建设 Prometheus/OpenTelemetry 指标、结构化日志、告警规则、带签名和幂等重试的 Webhook，以及企业微信、钉钉和邮件适配器；F6 的前端事件只作为用户体验信号，不能替代服务端生产监控。
