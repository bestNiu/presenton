## 2. 产品愿景与定位

### 2.1 产品愿景

> 让企业员工能够快速产出符合品牌、可编辑、可信和可协作的 PPT，同时把高价值专业场景中的知识、规则、审核和经验沉淀为组织能力。

### 2.2 产品定位

本产品不是单一“一键生成 PPT 工具”，也不是只服务竞标的专用系统，而是四层产品：

| 层次 | 面向对象 | 产品价值 |
| --- | --- | --- |
| 企业 PPT 公共中台 | IT、品牌、管理员和全体用户 | 统一身份、模型、文件、模板、素材、知识、版本、质量和审计 |
| 通用 PPT 工作台 | 全体员工 | 覆盖日常 PPT 创建、编辑、审阅、复用和导出 |
| 专业场景工作台 | 业务团队和专业部门 | 用专属数据、规则和流程提升复杂方案质量 |
| Presenton PPT 引擎 | 平台内部 | 提供大纲、页面、编辑、预览和可编辑导出 |

### 2.3 产品主张

- 对普通用户：从“找模板、拼内容、改格式”转为“讲清目标、确认结构、完善表达”；
- 对团队：从文件反复传递转为同一空间下的版本、评论和审阅；
- 对品牌：从事后人工纠错转为模板和质量规则前置；
- 对管理者：从无法衡量的个人劳动转为可追踪的效率、质量和资产；
- 对专业业务：从历史 PPT 复制转为有来源、有规则、有审核的方案生产；
- 对 IT：在一个底座上扩展场景，避免重复建设多套 AI PPT 系统。

## 3. 用户与核心任务

### 3.1 用户角色

| 用户 | 核心目标 | 主要痛点 | 首要能力 |
| --- | --- | --- | --- |
| 普通员工 | 快速制作日常 PPT | 不会设计、找模板慢、内容组织困难 | 快速创建、企业模板、AI 大纲与改页 |
| 项目经理 | 做周报、总结和方案汇报 | 数据分散、版本混乱、重复更新 | 从资料生成、版本、团队空间、复用 |
| 管理层汇报人 | 形成简洁可信的决策材料 | 内容太多、主线不清、时间紧 | 受众/时长驱动、摘要、质量检查 |
| 培训/职能人员 | 制作规范课件 | 品牌不统一、重复制作 | 固定模板、组件库、讲稿 |
| 审阅者 | 快速指出并确认问题 | 邮件/聊天意见散落 | 评论、指派、批准、版本对比 |
| 品牌/设计 | 保持品牌一致性 | 逐份改格式、模板失控 | 模板发布、锁定元素、品牌质检 |
| 空间管理员 | 管理部门资源与权限 | 文件散落、权限不清 | 成员、文件夹、审阅和导出策略 |
| 系统管理员 | 保证安全、成本和稳定性 | 模型/密钥分散、调用不可见 | 模型路由、配额、审计、监控 |
| Bid Manager | 组织完整竞标产出 | 跨部门、版本、响应遗漏 | 驾驶舱、需求矩阵、策略和评审 |
| 专业模块 Owner | 产出并审核专业方案 | 输入不一致、经验难复用 | 同源输入、专业草稿、来源和审核 |
| 管理层审批人 | 控制承诺和正式发布 | 承诺依据不清、风险不可追溯 | 承诺审批、质量门、冻结发布 |

### 3.2 Jobs to Be Done

#### 通用工作台

1. 当我只有一个主题时，帮助我在几分钟内形成可调整的大纲和初稿；
2. 当我已有 Word/PDF/Excel/PPT 材料时，帮助我提炼重点并保留来源；
3. 当公司要求统一品牌时，自动应用正确模板、字体、Logo 和布局；
4. 当我需要把长报告变成管理层汇报时，按受众和时长压缩主线；
5. 当团队一起修改时，让意见、版本和批准状态集中可见；
6. 当我正式导出时，帮我检查溢出、错字、数字、敏感信息和兼容问题；
7. 当我下次制作相似材料时，复用团队优秀页面、图表和组件。

#### 竞标工作台

1. 当收到 RFP 和方案资料时，快速形成项目画像、必答项和缺口；
2. 当跨部门开工前，先确认统一投标策略和客户主线；
3. 当专业模块并行编制时，保证使用同一版本输入和公司口径；
4. 当专家审核时，把机器可查问题提前处理并保留来源；
5. 当正式汇报时，输出已批准、无残留、关键数字一致的可编辑 PPT；
6. 当竞标结束时，沉淀答疑、问题和可复用资产。

## 5. 产品范围与边界

### 5.1 通用平台能力

- 个人、团队和部门空间；
- 演示文稿、文件夹、收藏、归档和回收站；
- 主题、资料、模板和已有 PPT 四种创建入口；
- 大纲生成、编辑、模板选择、页面生成和 AI 改页；
- 企业/部门/场景/团队/个人模板；
- 页面、图表、图片、图标和文案素材库；
- 评论、指派、审阅、批准和待办；
- 自动保存、命名版本、冻结、复制和版本查看；
- 品牌、排版、内容、敏感信息和兼容质量检查；
- PPTX/PDF 受控导出和审计；
- LiteLLM 模型路由、调用记录和用量统计；
- 场景扩展入口和统一任务中心。

### 5.2 竞标场景能力

- 竞标项目空间、专业角色和资料治理；
- 项目画像、来源、置信度、冲突和待确认；
- RFP 必答项、评分项、客户问题和需求矩阵；
- 投标策略纸及确认门禁；
- 医学、运营、数统首期专业模块；
- 承诺提出、依据和管理层审批；
- Gate 1/2/3、评审问题和整改；
- 20—30 页管理层摘要版组装；
- 竞标质量报告、冻结、答疑和复盘。

### 5.3 一期不做

- 实时多人同屏协同编辑；
- 无限制公网搜索、图库和图片生成；
- 普通用户自行配置外部模型 Key；
- 自动替代专业负责人做医学、统计、运营和承诺决策；
- 一次生成完整 120—150 页正式标书；
- 自动报价、合同生成与正式签署；
- 一期接完所有企业数据系统；
- 复杂知识图谱和完全自主 Agent；
- 面向外部客户的匿名公开分享。

## 7. 通用 PPT 工作台产品设计

### 7.1 工作台首页

#### 用户目标

用户在 10 秒内知道从哪里开始，并快速回到正在处理的材料。

#### 页面组成

- 快捷创建：主题、上传资料、企业模板、已有 PPT；
- 最近使用：名称、缩略图、空间、更新时间和状态；
- 待我处理：待审阅、被退回、质量阻断、生成失败；
- 推荐模板：企业默认、部门常用、场景推荐；
- 专业工作台：仅显示用户有权访问的场景；
- 使用提示：数据密级和 AI 使用边界。

#### 验收要点

- 普通用户不会被要求填写竞标字段；
- 最近文稿可在两次点击内打开；
- 失败任务和待办有明确下一步；
- 空间切换后所有列表同步变化。

### 7.2 四种创建入口

#### 从主题创建

输入：主题、目的、受众、时长、语言、语气、页数、场景和密级。系统先输出大纲，不直接生成全部页面。

#### 从资料创建

支持 Word、PDF、PPT、Excel、Markdown。用户可预览解析状态、选择允许使用的文件和引用模式。解析失败不能静默忽略。

#### 从模板创建

用户先选企业模板或固定场景模板，系统展示模板结构和必填槽位，可选择手填、AI 辅助或从资料填充。

#### 从已有 PPT 创建

支持复制、换模板、摘要、扩写和按新受众改版。原文稿保持不变，新文稿记录来源关系。

### 7.3 大纲与资料页

主要能力：

- 左侧资料列表与解析状态；
- 中间结构化大纲，可拖动排序、增删和锁定章节；
- 右侧生成设置和来源摘要；
- 支持“一页一结论”提示、页数预算和时长估算；
- 重新生成局部章节，不覆盖用户锁定内容；
- 资料型文稿显示来源数量和未引用资料提示。

业务规则：用户确认大纲后再进入批量生成；重新生成已确认大纲必须创建新大纲版本或保留撤销记录。

### 7.4 模板与风格页

- 仅展示用户有权使用的已发布模板；
- 支持企业、部门、场景、团队和个人筛选；
- 预览封面、目录、内容、图表和结尾页；
- 展示适用场景、Office/WPS 兼容状态和所需字体；
- 企业正式模板可锁定 Logo、页眉页脚和品牌区域；
- 用户可调整允许的配色、密度和图像风格，不能破坏锁定元素。

### 7.5 编辑器产品改造

现有编辑器作为核心，不在一期重做。需要增加：

- 工作台面包屑、空间和文稿状态；
- 保存/生成任务状态；
- AI 改当前页、压缩、扩写和改写；
- 页面来源与引用入口；
- 评论标记和待解决数量；
- 质量问题定位和一键跳页；
- 当前版本、冻结状态和发布入口；
- 受控内容被修改后的“需重新审核”提示；
- 页面/元素保存到个人或团队组件库。

### 7.6 审阅与评论

| 能力 | 说明 |
| --- | --- |
| 页面评论 | 关联页码、元素或全文 |
| 指派 | 指定处理人和截止时间 |
| 状态 | 待处理、已解决、重新打开 |
| 决策 | 批准、退回、附条件批准 |
| 策略 | 无审批、单级、双级、场景工作流 |
| 通知 | 站内待办，一期可不做实时消息 |
| 留痕 | 操作人、时间、版本和意见不可丢失 |

### 7.7 版本历史

- 自动保存用于防丢失，不等同正式版本；
- 用户可创建命名版本并填写变更说明；
- 审阅和冻结前自动创建快照；
- 冻结版本只读；继续修改需“创建新版本”；
- 一期支持版本级元数据和缩略图对比，精细元素 diff 可后续建设；
- 导出记录必须对应一个明确版本。

### 7.8 通用质量报告

按页面和规则分类展示：

- 品牌：Logo、色板、字体、页眉页脚；
- 排版：溢出、越界、字号、内容密度；
- 图片：清晰度、拉伸、缺失和授权；
- 内容：标题层级、重复、数字/日期/单位一致性；
- 安全：敏感词、个人信息和其他客户信息；
- 来源：资料型内容的引用完整性；
- 兼容：字体缺失、导出和 Office/WPS 风险。

结果分为提示、警告、阻断。用户点击问题可跳转页面；阻断项说明原因、修复建议和有权豁免的角色。

### 7.9 发布与导出

- 导出 PPTX、PDF 和预览图；
- 显示版本、模板、质量结果和审批状态；
- 对外/高密级材料可要求审批；
- 记录下载人、时间、格式、文件 hash；
- 冻结后修改不会覆盖已发布文件；
- 一期不提供匿名公网链接；
- 可配置水印和有效期作为 P1/P2 能力。

## 8. 模板与资产中心产品规划

### 8.1 模板分级

| 类型 | 创建人 | 可见范围 | 发布要求 |
| --- | --- | --- | --- |
| 企业模板 | 品牌/模板管理员 | 全公司 | 品牌和兼容审核 |
| 部门模板 | 部门模板管理员 | 指定部门 | 部门负责人/品牌按策略审核 |
| 场景模板 | 场景 Owner | 获授权场景用户 | 场景规则和兼容审核 |
| 团队模板 | 团队空间成员 | 团队 | 空间管理员审核可选 |
| 个人模板 | 用户 | 本人 | 无正式发布 |

### 8.2 模板生命周期

`草稿 → 待审核 → 已发布 → 已下线 → 已归档`

- 已发布模板不可原地修改，修改创建新版本；
- 下线不影响历史文稿继续显示和导出；
- 发布前必须生成预览并验证核心布局；
- 模板记录字体依赖、适用场景、布局标签和兼容状态；
- 管理员可设置默认模板和推荐排序。

### 8.3 首批布局规划

| 类别 | 布局 |
| --- | --- |
| 基础 | 封面、目录、章节、结尾、Q&A |
| 内容 | 单栏、双栏、三栏、图文、观点、对比、问题方案 |
| 数据 | KPI、表格、柱图、折线图、组合图 |
| 结构 | 流程、时间轴、组织架构、系统架构、矩阵 |
| 管理 | 周报状态、里程碑、风险、行动计划、决策事项 |
| 案例 | 客户案例、团队、能力、项目经验 |
| 竞标 | 中心/PI、策略链、需求响应、专业方案 |

首批总量 20—25 个，不追求模板数量，优先保证中文、品牌、内容密度和兼容性。

### 8.4 素材与组件

- 页面组件：整页或局部可复用结构；
- 图表组件：样式 + 数据 schema；
- 图片/图标：版权、来源、适用范围；
- 标准文案：公司介绍、资质、案例和统一口径；
- 收藏与最近使用；
- 保存到个人/团队；
- 申请提升为部门/企业资产；
- 资产下线、过期和授权撤销。

## 9. 专业场景框架产品规划

### 9.1 场景包组成

一个场景包必须定义：

- 场景名称、目标用户和创建入口；
- 创建字段和必传资料；
- 专属业务对象；
- 专属 AI 任务；
- 专属页面导航；
- 角色和权限；
- 工作流、门禁和审核人；
- 推荐/强制模板；
- 质量规则和验收指标；
- 运营指标和复盘方式。

### 9.2 场景候选池

| 场景 | 价值 | 复用程度 | 复杂度 | 建议顺序 |
| --- | ---: | ---: | ---: | --- |
| 竞标方案 | 极高 | 中 | 高 | 首个专业场景 |
| 管理层汇报 | 高 | 高 | 中 | 通用预设/P1 场景包 |
| 项目周报/月报 | 高 | 高 | 中 | P1 |
| 项目启动会 | 中/高 | 高 | 中 | P1 |
| 培训课件 | 中 | 高 | 低 | 通用预设 |
| 医学交流材料 | 高 | 中 | 高 | P2 |
| 数据分析汇报 | 高 | 高 | 中/高 | P2 |

新增场景的前提：有明确 Owner、稳定输入、可描述规则、代表性样例、人工审核边界和量化价值。不能仅因为“有人想要一个入口”就复制场景。

## 10. 竞标工作台详细规划

### 10.1 产品目标

将竞标准备从“多部门各自找历史 PPT 并人工合并”转为：同一项目输入、统一竞标主线、结构化专业内容、来源与承诺可追踪、评审问题可闭环、PPT 可编辑和版本可冻结。

### 10.2 项目驾驶舱

展示：

- 项目基本信息、密级、阶段和截止时间；
- 当前流程阶段和下一门禁；
- 项目成员及九类专业角色；
- 资料完整度、待确认字段和冲突；
- 需求矩阵覆盖率；
- 各模块状态、负责人和逾期；
- Gate 检查和阻断问题；
- 最新 PPT 版本和导出状态；
- 最近操作与风险提醒。

关键动作只显示当前状态和角色允许的动作，例如“确认策略纸”“提交专业审核”“开启 Gate 2”。

### 10.3 项目资料

一期标准分类：RFP、方案摘要、完整方案、IB、既往研究、客户会议纪要、历史竞标材料、公司素材、人员简历、中心/PI 数据。

功能：上传、指纹、版本、分类、解析、预览、确认有效版本、标记替代和冲突。RFP 与方案缺失时提示阻断影响，不允许假装资料完整。

### 10.4 项目画像

字段分组：药物、适应症、开发、设计、规模、安全、检测、客户和缺口。

每个字段显示：值、事实/推断、来源文件与页码、置信度、审核状态、修改人和版本。用户可以确认、修改、退回、标记待确认。无来源推断不能显示为已确认事实。

### 10.5 需求矩阵

字段：需求类别、原文、必答/评分、分值、来源、责任部门、负责人、目标模块、目标页面、状态和回复。

关键指标：必答项识别准确率、必答项覆盖率、无人认领项、逾期项。Gate 2 前必答项覆盖率必须 100%。

### 10.6 投标策略纸

六类要素：项目判断、客户担忧、解决方案、差异化优势、关键承诺、需客户共同决策事项。

规则：

- 担忧与方案可建立一一对应；
- 差异化优势必须关联案例或数据；
- 关键承诺必须有依据和审批状态；
- Bid Manager 确认后才开放专业模块正式生成；
- 上游画像重大变化时策略标记待复核。

### 10.7 专业工作台

首期模块：医学、运营、数统。

统一页面结构：

1. 上游输入：画像、策略、需求和资料版本；
2. 模块规则与缺失输入；
3. AI 生成任务和版本；
4. 结构化内容块、表格和页面建议；
5. 每项内容的来源、置信度和状态；
6. 编辑、提交、退回、批准；
7. 本模块质量问题和需求覆盖。

专业模块不能各自上传一套互不相同的项目基础信息。有效方案版本变化时，受影响模块提示重新评估。

### 10.8 承诺审批

服务承诺作为独立对象管理：内容、类型、适用条件、历史依据、风险等级、提出人、审批人和状态。

状态：`候选 → 待审批 → 已批准 / 已拒绝 → 已撤销`。未经批准的承诺不能进入正式 PPT；修改已批准承诺创建新版本并重新审批。

### 10.9 三道评审门

#### Gate 1 专业正确性

系统检查来源、资料版本、未确认字段和模块审核状态；专业专家判断医学、统计、中心和时间计划。

#### Gate 2 客户决策逻辑

检查必答覆盖、承诺审批、定制化和通用内容；由未直接参与撰写的人从客户角度评审。

#### Gate 3 演练与发布

检查残留、数字一致、未批准内容、汇报时长、排版字体和兼容；人工完成正式演练与应答分工。

每道门都有问题清单、责任人、期限、复核人和是否准入下一门。

### 10.10 PPT 组装与版本

一期输出 20—30 页管理层摘要版。用户选择已批准模块、页面预算和竞标模板，系统生成组装预览。进入编辑器后，受控专业内容修改会提示重新审核。

冻结版本包含来源清单、审核记录和质量报告。后续 60—80 页正式汇报版和 120—150 页完整标书在 MVP 验证后建设。

### 10.11 答疑与复盘

- 基于画像、风险和最终内容生成候选问题；
- 记录问题、建议回答、证据和应答人；
- 竞标后记录结果、客户反馈和材料问题；
- 提议将优秀页面/组件脱敏后入库；
- 高频评审问题转为规则或模板改进项。

## 11. 权限、审阅与数据使用体验

### 11.1 空间角色

| 角色 | 典型权限 |
| --- | --- |
| 空间管理员 | 成员、文件夹、模板、审阅和导出策略 |
| 编辑者 | 创建、编辑、评论、发起审阅 |
| 审阅者 | 查看、评论、批准或退回 |
| 查看者 | 只读，下载按策略 |

### 11.2 竞标角色

Bid Manager、模块 Owner、专业审核人、客户视角评审人、汇报人/查看者、管理层审批人。角色决定业务动作，不替代空间访问权限。

### 11.3 密级提示

用户创建文稿/项目时选择或继承 L1—L4。界面应清楚展示：

- 当前密级；
- 允许的模型和知识范围；
- 是否允许导出/分享；
- 是否需要审批；
- 哪些能力因密级被禁用。

不要只在服务条款中描述数据边界，关键动作处必须有上下文提示。

## 12. 关键用户旅程与验收

### 12.1 旅程 A：从主题生成管理汇报

1. 用户点击快速生成；
2. 输入主题、管理层受众、15 分钟和 10 页；
3. 选择企业模板；
4. 确认大纲；
5. 生成可编辑页面；
6. 修改两页并运行质量检查；
7. 创建命名版本并导出 PPTX。

验收：10 页 ≤5 分钟、主要元素可编辑、品牌 100% 符合、无明显溢出、导出有审计。

### 12.2 旅程 B：从 Word/PDF 生成项目总结

1. 上传 2—3 份资料；
2. 查看解析结果和失败提示；
3. 选择资料生成大纲；
4. 查看关键内容来源；
5. 生成、审阅和退回；
6. 修改后批准并冻结。

验收：资料版本可追踪、引用可定位、评论与批准绑定版本、冻结后不能覆盖。

### 12.3 旅程 C：团队模板和页面复用

1. 用户在编辑器保存优秀页面到团队空间；
2. 空间管理员审核并加标签；
3. 其他用户搜索并插入；
4. 页面适配当前模板；
5. 记录复用次数。

验收：无权限用户不可见；原资产下线后不破坏已使用文稿；复用可统计。

### 12.4 旅程 D：竞标画像到策略确认

1. Bid Manager 创建项目并授权成员；
2. 上传并确认 RFP、方案和 IB；
3. 系统抽取画像与需求矩阵；
4. 医学审核画像，Bid Manager 处理冲突；
5. 生成并编辑策略纸；
6. 承诺进入审批；
7. Bid Manager 确认策略，开放专业模块。

验收：字段来源可定位、待确认不被伪装、必答识别 ≥95%、策略未确认前正式生成受阻。

### 12.5 旅程 E：专业模块到正式导出

1. 医学/运营/数统生成并审核内容；
2. Gate 1 处理来源和专业问题；
3. Gate 2 达到必答覆盖 100%；
4. 组装摘要版并进行页面编辑；
5. Gate 3 清零残留和未批准内容；
6. 冻结、导出并登记对外发送。

验收：关键数字来源 100%、高风险结论审核 100%、未经批准承诺 0、其他客户/药物残留 0。

## 15. MVP 验收与北极星指标

建议采用：

> 每月通过平台完成“生成/编辑—质量检查—成功导出”的有效企业 PPT 数。

> 通过正式审核门并完成冻结的竞标交付包数量，以及其初稿准备时间降低比例。

## 16. 数据埋点规划

### 16.1 核心事件

| 事件 | 关键属性 |
| --- | --- |
| `workspace_opened` | workspace_type, role |
| `presentation_create_started` | creation_mode, scene, source_count |
| `outline_generated` | model_alias, duration, slides, success |
| `outline_confirmed` | edit_count, duration |
| `slides_generated` | template, slides, duration, success |
| `slide_ai_edited` | action, page_type, accepted |
| `quality_run_completed` | rules, warning_count, blocker_count |
| `review_submitted/decided` | policy, duration, decision |
| `version_frozen` | scene, quality_status |
| `presentation_exported` | format, pages, release_type |
| `asset_saved/reused` | asset_type, scope |
| `bid_gate_completed` | gate, issues, duration |

产品分析事件与合规审计事件分开：分析数据不存敏感正文，审计记录强调操作可追溯。

### 16.2 漏斗

通用：创建开始 → 输入完成 → 大纲确认 → 页面生成 → 编辑 → 质量检查 → 导出。

竞标：项目创建 → 资料有效 → 画像确认 → 策略确认 → 模块批准 → Gate 2 → 冻结 → 对外发送。

通过漏斗定位放弃点，不能仅以“模型输出完成”代表用户成功。

## 17. 试点与推广计划

### 17.1 通用工作台试点

建议选择 20—50 人，覆盖：IT/产品、项目管理、BD/市场、职能培训和管理汇报人员。每类至少准备一个真实任务：

- 管理层阶段汇报；
- 项目总结；
- 周报/月报；
- 培训或制度课件；
- 数据分析汇报。

试点用户不是只看演示，而是在两周内至少完成一份真实 PPT。

### 17.2 竞标试点

选择资料完整、时间不极端紧张、业务 Owner 能投入的真实 III 期项目。先用系统形成画像、矩阵、策略和三模块摘要版，同时保留当前人工方法作为对照。

### 17.3 试点过程

| 时间 | 动作 |
| --- | --- |
| 启动前 | 培训、数据边界、样例和反馈渠道 |
| 第 1 周 | 陪跑，记录阻塞和失败，不频繁扩范围 |
| 第 2 周 | 完成真实输出，收集耗时和修改量 |
| 评审 | 指标、问题、是否继续、范围调整 |
| 修复 | P0/P1 问题，模板和规则迭代 |
| 发布 | 手册、Owner、支持与运营机制 |

### 17.4 反馈分类

- Bug：与产品承诺不一致；
- 内容质量：模型、数据、Prompt 或规则问题；
- 模板质量：布局、字体、品牌或兼容；
- 易用性：流程、信息和反馈不清；
- 新需求：当前范围外；
- 治理问题：数据无 Owner、规则未确认或权限不清。

不同类别由不同 Owner 处理，避免把所有问题都归为“模型不好”。

## 18. 产品运营与治理

### 18.1 运营角色

| 角色 | 职责 |
| --- | --- |
| 产品 Owner | 路线图、范围、指标和用户反馈 |
| 平台管理员 | 用户、空间、配置和支持 |
| 模板管理员 | 模板发布、品牌和兼容 |
| 数据 Owner | 数据准确、日期、来源和授权 |
| 场景 Owner | 规则、流程、样例和业务验收 |
| AI/评测 Owner | Prompt、模型、黄金集和质量趋势 |
| 安全/审计 | 数据边界、事件检查和应急 |

### 18.2 模板运营

- 每月查看模板使用、导出成功和质量问题；
- 合并重复模板、下线低质量版本；
- 从高频用户问题补充布局；
- 重要品牌升级创建新版本，不覆盖历史；
- 发布说明说明适用场景和字体依赖。

### 18.3 场景运营

- 每季度评审场景使用量、业务收益和规则质量；
- 评审退回原因沉淀为规则、样例或输入提示；
- 场景输入或审核长期缺失时暂停扩展功能；
- 场景 Owner 对业务准确性负责，IT 对系统能力负责。

### 18.4 内容资产治理

从个人/项目内容进入团队或企业库需要：脱敏、来源、授权、Owner、有效期和审核。历史竞标项目内容不能因为“效果好”就自动进入公共资产库。

## 20. 依赖与前置条件

### 20.1 通用平台

- 确认企业品牌规范和字体白名单；
- 选定通用试点场景和用户；
- 确认空间、分享、下载和审阅策略；
- LiteLLM 提供可用模型别名与配额；
- 确认测试/生产环境和数据边界；
- 至少 5 个核心布局设计稿和验收样例。

### 20.2 竞标场景

- 选定真实 III 期项目并授权；
- Bid Manager 和医学/运营/数统 Owner 明确；
- 项目画像、需求矩阵和策略纸字段冻结；
- 每模块提供字段、规则、正反样例；
- 公司口径库 V1；
- 服务承诺审批人和三道门责任人明确。

### 20.3 进入开发的判断

通用底座开发可以先开始；竞标专业模块不得在规则和 Owner 不明确时假设业务逻辑。可以并行做访谈和原型，但不能把未确认的讨论稿当作正式验收标准。

## 21. 产品风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 被竞标绑死 | 全部导航、字段都围绕项目 | 通用工作台先验收，场景包隔离 |
| 退化为一键生成器 | 缺少空间、版本、审阅和质量 | 这些能力纳入通用 P0 |
| 追求模板数量 | 大量模板但不可用 | 20—25 个高频布局，使用和兼容验收 |
| 用户不信任内容 | 无来源、错数字 | 资料引用、事实类型、质量检查 |
| 专业场景越权 | AI 自动作承诺 | 独立承诺对象和人工审批 |
| 用户流程过重 | 普通 PPT 也需多道审核 | 通用轻流程、策略可选、专业强流程 |
| 试点无代表性 | 只用演示材料 | 真实通用任务 + 真实竞标项目 |
| 业务投入不足 | 无规则和样例 | Owner/交付物作为启动条件 |
| 生成好看但不可编辑 | 页面图片化 | 可编辑性作为 P0 验收 |
| 使用成本失控 | 默认高价模型 | 模型别名、任务路由、成本看板 |
| 资产泄密 | 项目页面直接入公共库 | 脱敏、授权和审核后才能提升 scope |

## 22. 产品决策清单

### 22.1 需立即确认

1. 是否认可四层产品定位；
2. 通用首批 3 类场景和试点用户；
3. 企业模板与品牌 Owner；
4. 通用空间、审阅、导出和密级策略；
5. 竞标真实试点项目和模块 Owner；
6. 双 MVP 指标和基线 Owner；
7. 一期账号还是直接 SSO；
8. 正式试点是否直接启用 PostgreSQL/对象存储。

### 22.2 可在试点后决定

- 实时多人编辑；
- 完整外部分享；
- 更多场景包顺序；
- CTMS/CDE/智策深度集成；
- 完整技术标书；
- 中心推荐和入组预测；
- 图片生成和公网知识策略。

## 23. 产品完成定义

### 23.1 通用工作台

- 不进入任何专业场景也可完成创建到导出；
- 四种创建入口、生成、编辑、审阅、版本、质量和导出形成闭环；
- 企业模板与主要元素可编辑，Office/WPS 通过；
- 空间权限、模型和导出行为可追溯；
- 至少 3 类真实场景、20—50 人试点并达到目标；
- 用户手册、反馈流程、模板 Owner 和运营机制就绪。

### 23.2 竞标工作台

- 一个真实项目完成画像、矩阵、策略、三模块和三道门；
- 正式关键数字来源 100%，高风险内容审核 100%；
- 未批准承诺和其他客户/药物残留均为 0；
- 输出 20—30 页品牌一致、可编辑的核心 PPT；
- 审核、质量、冻结、导出和复盘资产完整；
- 业务时间与质量指标达到约定阈值。

---

## 24. 总结

企业 PPT 制作中台的产品成功不应以“AI 生成了多少页”为标准，而应以三件事衡量：

1. 普通员工是否能稳定完成真实日常 PPT，减少结构和排版劳动；
2. 企业是否获得统一模板、协作版本、质量、安全和资产复用能力；
3. 竞标等专业场景是否能将数据、规则、审核和经验真正沉淀下来。

产品建设顺序必须保持：

> 先做好全员可用的通用工作台，再建立稳定的场景扩展能力，然后用竞标场景验证专业深度，最后扩展更多业务工作台。
