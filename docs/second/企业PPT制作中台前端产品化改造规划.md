# 企业 PPT 制作中台前端产品化改造规划

> 文档版本：V1.0
>
> 编制日期：2026-08-14
>
> 适用分支：`enterprise/internal-dev`
> 适用范围：T0—T47 已落地能力的前端产品化改造，不新增 T48 之后的后端业务范围

## 1. 规划背景

当前企业 PPT 制作中台已形成较完整的后端能力，覆盖企业工作区、通用 PPT、竞标工作台、模板、文档知识、企业素材、评审、质量、冻结、交付与完整性处置等领域。

前端已接入绝大多数企业 API，但整体仍偏向“功能验证台”：页面能够触发接口，却缺少统一的信息架构、任务引导、业务上下文、精细状态反馈和企业级视觉一致性。用户需要理解大量技术概念和后台状态，才能完成一条业务流程。

本轮改造的核心不是继续增加入口，而是把 T0—T47 已有能力组织成可理解、可操作、可持续使用的企业产品。

## 2. 当前问题结论

### 2.1 总体判断

| 维度 | 当前判断 | 目标 |
| --- | --- | --- |
| 后端能力接入 | 较高，企业 API 客户端已有 104 个方法 | 保持完整，消除孤立入口 |
| 页面覆盖 | 主要业务均有页面 | 从“有页面”升级为“有业务工作台” |
| 操作闭环 | 接口层基本闭环，用户流程不连续 | 关键流程具有明确的下一步和完成标准 |
| 信息架构 | 企业功能集中在一个 Workspace 入口下 | 建立稳定的企业中台导航和空间上下文 |
| 视觉体验 | 多套风格、中英文混用、硬编码样式较多 | 建立统一设计系统和中文产品语言 |
| 错误处理 | 大块并行加载，一个失败可能影响整页 | 区块级加载、错误翻译、局部重试和降级 |
| 前端测试 | 仅少量基础测试，缺少企业流程测试 | 建立组件、契约和 E2E 三层保障 |

### 2.2 主要体验缺口

1. 工作区、文档、素材、模板、竞标、交付之间缺少稳定的统一导航；
2. 工作区成员、角色、文件夹和审计等基础管理缺少完整前端；
3. 通用 PPT 创建入口较多，但缺少统一步骤式创建向导；
4. 竞标能力集中在一个超长页面，未按项目阶段组织；
5. 文档知识中心只具备上传、检索和生成的最小操作面；
6. 模板发布仍需要用户理解模板 ID、发布标识等技术字段；
7. 评审、引用和素材以多个浮动按钮嵌入编辑器，入口分散；
8. 交付中心缺少完整证据详情、授权策略和事件时间线；
9. 页面错误提示直接暴露接口错误，缺少业务解释和恢复动作；
10. 企业页面缺少端到端自动化测试。

## 3. 改造目标

### 3.1 产品目标

- 让普通企业用户无需理解内部 ID、接口状态和数据库概念即可完成操作；
- 让通用 PPT 与竞标 PPT 共用一致的工作区、资料、模板、评审和交付体验；
- 让每个关键任务都能回答“当前在哪一步、为什么不能继续、下一步做什么”；
- 让管理员能够从统一运营入口管理用户、存储、巡检、异常和平台配置；
- 让页面在部分接口异常时仍能展示其他可用信息，并提供明确恢复动作；
- 建立覆盖 T0—T47 关键流程的前端自动化验收体系。

### 3.2 量化目标

| 指标 | 目标值 |
| --- | --- |
| 新用户从登录到创建第一份通用 PPT | 3 分钟以内 |
| 新建竞标项目完成基础画像与资料录入 | 10 分钟以内 |
| 关键任务下一步可识别率 | 100% |
| 企业页面未处理 500/422 原始错误展示 | 0 |
| 企业主流程 E2E 覆盖 | 不少于 8 条 |
| 企业前端关键 API 契约覆盖 | 不少于 90% |
| 页面首屏独立区块失败隔离率 | 100% |
| 中英文混用页面 | 0 |

## 5. 优化项总表

### 5.1 P0：阻断性问题

| 编号 | 优化项 | 具体内容 | 验收标准 |
| --- | --- | --- | --- |
| FE-P0-01 | 修复工作区初始化阻断 | 配合后端修复工作区创建审计外键问题；前端不再无限重复初始化 | 首次登录可创建个人空间，刷新后幂等返回同一空间 |
| FE-P0-02 | 初始化失败降级 | 个人空间初始化失败时仍展示可诊断页面，不重复触发请求 | 页面展示错误编号、重试和联系管理员入口 |
| FE-P0-03 | 错误翻译层 | 将 400/401/403/404/409/422/429/500 转换为业务语言 | 不直接向用户展示 `Internal server error` 等原始文本 |
| FE-P0-04 | 区块级故障隔离 | 删除首页单个大 `Promise.all` 的全页失败模式 | 通知失败不影响文稿列表，质量失败不影响工作区首页 |
| FE-P0-05 | 长任务状态恢复 | 生成、解析、导出、巡检支持刷新后继续查看 | 浏览器刷新后仍能恢复任务状态和最终结果 |

## 6. 分模块改造方案

### 6.1 企业工作区

目标页面：

- `/workspace`：企业首页；
- `/workspace/presentations`：文稿列表；
- `/workspace/tasks`：我的待办；
- `/workspace/settings/general`：基础信息；
- `/workspace/settings/members`：成员角色；
- `/workspace/settings/folders`：文件夹；
- `/workspace/settings/governance`：治理策略；
- `/workspace/settings/audit`：审计记录。

核心改造：

1. 将当前首页的大型页面拆为首页、文稿、任务和设置；
2. URL 中保留工作区上下文，但由全局状态统一维护；
3. 支持按文件夹、场景、状态、创建方式和负责人筛选；
4. 文稿卡片直接展示质量、评审、引用、冻结和交付状态；
5. 为无工作区、无权限、空列表和初始化失败提供独立页面。

### 6.2 通用 PPT 工作台

创建向导建议：

```text
步骤 1：选择创建方式
主题生成 | 企业资料 | 企业模板 | 空白文稿 | 导入文件

步骤 2：配置内容
主题、受众、页数、语言、语气、资料和生成约束

步骤 3：选择设计
模板预览、品牌规则、版式和默认字体

步骤 4：确认并生成
输入摘要、预计任务、资料版本和创建位置
```

文稿列表应提供继续编辑、提交评审、运行质检、查看阻断、冻结和交付的上下文操作，避免把所有治理动作直接平铺在首页。

### 6.3 竞标工作台

项目详情拆分为：

1. 项目总览：进度、风险、成员、截止日期和下一步；
2. 资料与理解：招标文件、结构化画像、冲突和确认；
3. 需求矩阵：需求、来源、责任人、状态、响应和批量导入；
4. 策略纸：差异化价值、客户关注、风险、取舍和版本确认；
5. 专业协作：医学、运营、数统独立编辑与审核；
6. Gate 看板：问题、责任人、证据、解决状态和通过条件；
7. 组装与版本：模块选择、模板、manifest、质量和冻结；
8. 交付：导出、授权、下载、撤销和归档。

必须新增项目成员管理、Gate 问题处置和项目活动时间线，避免只支持后台已有的部分动作。

### 6.4 文档知识中心

列表页只负责筛选、上传和批量操作；详细信息进入侧边抽屉或详情页。解析过程统一采用任务组件展示：排队、解析、切片、索引、完成或失败。

知识大纲不应直接在卡片中展示完整内容，应进入大纲编辑器，支持页级调整、来源预览、引用缺口提示和单页重生成。

### 6.5 模板与品牌

模板发布流程改为：选择模板 → 查看校验 → 填写发布信息 → 选择范围 → 提交审批。模板 ID、版本关系和兼容校验结果由系统自动处理。

模板卡片必须包含缩略图、适用场景、品牌、页型数量、当前版本、发布状态和最近使用情况。

### 6.6 企业资产

保留现有搜索、收藏、推荐、提升审批和重复治理能力，将卡片上的复杂操作收敛到详情抽屉。资产中心拆分“发现”和“治理”两类视图，避免普通用户看到大量管理动作。

### 6.7 评审、质量与引用

编辑器右侧统一为企业工具栏：

```text
素材 | 来源 | 评审 | 质量 | 版本
```

点击质量问题或引用异常时，应定位到具体页面和元素。评审中心采用任务列表与文稿详情双层结构，支持负责人、截止时间、阻断状态和批量处理。

### 6.8 交付与完整性治理

交付中心从聚合表升级为“列表 + 详情抽屉”。详情包括：

- 文件属性和 SHA-256；
- 冻结快照和 manifest；
- 引用证据和完整性；
- 下载授权列表；
- 下载与撤销活动；
- 平台签发凭证；
- 证据包下载和复核；
- 关联异常处置单。

异常处置使用正式表单，支持负责人、处置类型、说明、附件、复检和关闭，不再使用浏览器原生输入框。

### 6.9 管理后台

统一改为中文，并重新组织为：用户、工作区、模型服务、存储、完整性巡检。平台级巡检页面增加运行进度、失败工作区下钻、任务取消状态、告警说明和处置入口。

### 7.2 状态与请求治理

- 工作区上下文由顶层 Provider 维护；
- 服务端状态使用统一请求缓存层，避免各页面重复手写加载逻辑；
- 长任务采用统一 `TaskProgress` 模型和轮询恢复机制；
- 页面请求按区块独立，允许部分成功；
- 错误对象统一包含 `code`、`title`、`detail`、`retryable` 和 `trace_id`；
- 表单统一处理脏数据、离开确认、乐观锁冲突和重复提交；
- URL 保留可分享的筛选、工作区、项目和详情状态。

## 8. 设计与交互规范

### 8.1 统一状态语言

| 后端状态 | 用户文案示例 |
| --- | --- |
| `draft` | 草稿 |
| `pending` | 等待处理 |
| `in_review` | 审核中 |
| `approved` | 已批准 |
| `rejected` | 已退回 |
| `frozen` | 已冻结 |
| `ready` | 可交付 |
| `revoked` | 已撤销 |
| `failed` | 处理失败 |

状态颜色必须全局统一：成功使用绿色，进行中使用蓝色，待处理使用黄色，阻断和失败使用红色，归档和只读使用灰色。

### 8.2 关键交互原则

1. 破坏性操作必须使用确认弹窗并说明影响范围；
2. 长任务必须展示阶段、耗时和可恢复状态；
3. 禁用按钮必须同时说明不可用原因；
4. 业务阻断必须提供跳转整改入口；
5. 技术 ID、哈希和 manifest 默认折叠，在专业详情中展开；
6. 表格行操作不超过三个，其余进入“更多”；
7. 空状态必须说明如何产生第一条数据；
8. 403、409、422 不作为通用错误处理，应转换为权限、冲突和规则提示。

## 9. 实施阶段

### F0：稳定性修复

范围：FE-P0-01—FE-P0-05。

交付：工作区初始化恢复、错误翻译、区块隔离、任务恢复组件。完成后才能开展真实业务验收。

### F1：企业壳层与工作区

范围：企业导航、顶部工作区上下文、首页、文稿列表、成员、角色、文件夹和工作区设置。

交付：用户登录后可以完成空间选择、组织内容和成员协作，不再依赖单一超长首页。

### F2：通用 PPT 主流程

范围：统一创建向导、文稿状态中心、编辑器企业侧栏、评审与质量联动。

交付：主题、文档、模板和空白四类创建方式形成一致体验。

### F3：竞标工作台产品化

范围：六阶段导航、任务面板、需求矩阵、专业协作、Gate 看板、版本与交付。

交付：竞标项目按阶段推进，不再依赖单页表单堆叠。

### F4：知识、模板与资产

范围：文档详情与版本、知识大纲编辑器、模板可视化发布、资产详情与治理。

交付：企业内容资源形成可发现、可理解、可治理的产品界面。

### F5：可信交付与管理员运营

范围：冻结预检、交付证据树、授权配置、异常处置、平台巡检和后台中文化。

交付：T35—T47 从接口能力升级为完整运维和业务处置体验。

### F6：质量与发布

范围：E2E、视觉回归、可访问性、性能、埋点和用户验收。

交付：形成前端发布门禁和正式试点准入结论。

## 10. 测试规划

### 10.1 单元与组件测试

- 工作区上下文和角色判断；
- 状态映射和错误翻译；
- 创建向导各步骤；
- 长任务恢复；
- 冻结阻断项；
- 交付完整性状态；
- 危险操作确认；
- 空、加载、失败和只读状态。

### 10.2 API 契约测试

- OpenAPI 与 TypeScript 类型一致性；
- 关键响应字段变更检测；
- 401/403/409/422/429/500 错误映射；
- 分页、筛选和排序参数；
- 幂等键与乐观锁冲突。

### 10.3 E2E 主流程

1. 登录 → 个人空间初始化 → 创建空白 PPT；
2. 团队空间 → 邀请成员 → 设置角色 → 创建文件夹；
3. 主题生成 → 编辑 → 质量检查 → 提交评审 → 冻结；
4. 文档上传 → 解析 → 检索 → 生成大纲 → 创建 PPT；
5. 模板登记 → 审核 → 发布 → 设为默认 → 创建 PPT；
6. 保存素材 → 发布 → 收藏 → 插入 → 创建新版；
7. 竞标创建 → 画像 → 需求 → 策略 → 模块 → Gate → 冻结；
8. 通用/竞标交付 → 授权下载 → 撤销；
9. 完整性异常 → 隔离 → 复检 → 恢复；
10. 普通用户越权访问管理员页面被拒绝。

## 11. 验收标准

### 11.1 功能验收

- T0—T47 每项已有后端能力均有明确的前端入口或管理界面；
- 普通用户、编辑者、审阅者、空间管理员和平台管理员看到符合角色的动作；
- 通用 PPT 与竞标 PPT 能从创建一直走到受控交付；
- 文档、模板和素材可以从独立中心进入 PPT 创建与编辑流程；
- 完整性异常可以在前端完成指派、说明、复检和关闭。

### 11.2 体验验收

- 用户在任意页面均可识别当前工作区和返回路径；
- 关键操作均有加载、成功、失败和恢复反馈；
- 禁用操作有明确原因；
- 无浏览器原生 `alert`、`confirm`、`prompt`；
- 无中英文混用和未经翻译的后台枚举；
- 不直接展示服务器堆栈或通用 Internal Server Error。

### 11.3 工程验收

- 页面按领域拆分，不再出现承载完整领域流程的超长单文件；
- 企业共享组件进入统一目录并具备 Story/测试；
- 主流程 E2E 全部进入 CI；
- 前端构建、Lint、类型检查、测试和视觉回归通过；
- 关键页面具备错误率、接口耗时和任务耗时监控。

## 12. 推荐执行顺序

1. 先完成 F0，解决当前阻断和错误处理问题；
2. 再完成 F1，建立所有后续页面共同依赖的企业壳层与工作区上下文；
3. 优先完成 F2 通用 PPT，因为它是中台最广泛的业务入口；
4. 完成 F3 竞标工作台，保留专业场景差异但复用通用组件；
5. 完成 F4 内容资源中心，使知识、模板和素材真正服务制作流程；
6. 完成 F5 可信交付与运维闭环；
7. 以 F6 的自动化测试、性能和用户验收作为正式试点门禁。

在 F0—F2 完成前，不建议继续横向扩展新的企业场景页面；否则将继续增加接口入口和页面数量，但无法改善用户对“前端简陋、流程不清晰”的核心感受。
